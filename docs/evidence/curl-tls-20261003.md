# Sonoma curl TLS backend on iPadOS 17

## Runtime evidence

USB SSH, Sonoma 14.0 chroot, 2026-10-03. The same `/usr/bin/curl`
executable was used for both requests. No proxy or verification bypass was
added.

Default backend (`curl -V`):

```text
curl 8.1.2 (x86_64-apple-darwin23.0) libcurl/8.1.2 SecureTransport (LibreSSL/3.3.6)
curl: (60) SSL certificate problem: Couldn't understand the server certificate format
curl_status=60
```

With `CURL_SSL_BACKEND=openssl`, `curl -V` marks LibreSSL as active:

```text
curl 8.1.2 (x86_64-apple-darwin23.0) libcurl/8.1.2 (SecureTransport) LibreSSL/3.3.6
HTTP/2 200
default_ca_status=0
```

Runtime-confirmed: selecting the bundled alternative TLS backend restores
this HTTPS request with the existing default CA store. It does not establish
why SecureTransport's parser failed internally, or prove Safari works.
The version's build triplet is printed verbatim; it does not identify the
slice executed by the launcher.

Negative controls after deployment:

```text
curl: (60) SSL certificate problem: certificate has expired
expired_certificate_status=60
curl: (60) SSL: no alternative certificate subject name matches target host name 'wrong.host.badssl.com'
wrong_host_status=60
```

## Change and verification

`run_bash.sh` defaults `CURL_SSL_BACKEND` to `openssl`, preserving explicit
operator overrides. `configure_terminal_cli.sh` appends the same export once
to the existing Terminal configuration without replacing user content.
Both package installation and deep repair already invoke this installer.
Existing Terminal shells can source `/Users/root/.bashrc`; new windows load it.

Two executable shell configuration tests verify repeat installation, retained
user content and explicit overrides. Shell syntax checks pass. Installed CLI
request returns HTTP/2 200 and exit 0. Invalid certificates remain rejected.

Device originals: `/var/jb/var/mobile/sonoma-workspace-originals/curl-tls-20261003/`.
This change does not alter Safari, Mail, Weather or Messages networking.
